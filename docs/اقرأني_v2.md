# عين الحملة — الإصدار 4 (مميزات الحج)

> الملف اسمه `اقرأني_v2` لأن المجلد بدأ من الإصدار 2، ومحتواه محدَّث حتى الإصدار 4. التحديثات الأحدث في القسم الأخير.

**الهدف الرئيسي (موحّد في كل عناصر المشروع):**
منظومة ذكية تتابع حضور أفراد الحملة وتحميهم من الانفصال.. حضورهم تحت نظرك في كل لحظة.
بعبارة أخرى: تقليل حالات ضياع الحجاج وتأخر اكتشافها، وتحسين تنظيم الحملة وسلامة الحجاج، بلا أي أجهزة أو أساور.

## التشغيل (3 خطوات)

### 1) القاعدة على Supabase (مرة واحدة)
Supabase ← مشروع «عين الحملة» ← SQL Editor ← New query:
1. الصقي `database/04_migration_v2.sql` كاملاً ← Run. آخر نتيجة لازم تظهر **21**.
2. Query جديدة ← الصقي `database/05_seed_v2.sql` ← Run (بيانات تجريبية للمناسك والتجمعات).
3. Query جديدة ← الصقي `database/06_offline_map.sql` ← Run. يضيف دالة الخريطة بدون إنترنت `app_map_data`، ويصحّح أوقات المناسك والتجمعات على الترتيب الشرعي بتوقيت مكة. آخر نتيجة تعرض جدول المناسك الثمانية مرتبة.

> القاعدة الحية فيها أصلاً الملفات 01 و02 و03، فلا تعيدي تشغيلها. للتركيب من الصفر على قاعدة فاضية شغّلي الستة بالترتيب.
> ملفا 04 و06 آمنان لإعادة التشغيل. ملف 05 يُشغَّل مرة واحدة فقط، والأفضل تشغيل 05 و06 في نفس اليوم.
> إذا كنتِ شغّلتِ 04 قبل كذا وطلع لك خطأ `55P04 unsafe use of new value`، فقد انحلّ في النسخة الحالية: أسطر ENUM صارت داخل `BEGIN … COMMIT`.

### 2) الموقع ولوحة التحكم
افتحي مجلد `website` في VS Code ← Live Server ← `dashboard/login.html`
(أو `run_all.sh` يشغّل الموقع والتطبيق معاً).

### 3) التطبيق
```
cd flutter_app
flutter pub get
flutter run -d chrome
```
للنشر: `نشر_عين_الحملة.command` يبني التطبيق داخل `website/app`، ثم يُسحب مجلد `website` نفسه (اللي فيه `index.html` و`app` و`dashboard`) إلى صفحة Deploys في Netlify.

**الموقع المنشور (v4):** https://ain-alhamla2.netlify.app
- التطبيق: https://ain-alhamla2.netlify.app/app/
- لوحة التحكم: https://ain-alhamla2.netlify.app/dashboard/login.html

> Netlify يخلي المشاريع الجديدة خاصة تلقائياً: بعد أي مشروع جديد لازم **Make public**. والرابط القديم ain-alhamlaa تابع لحساب ثاني، وما عاد يُحدَّث.

## ملاحظة أمنية
كل كتابة وكل قراءة حساسة (البيانات الطبية، الجواز، جهات الطوارئ، المواقع، الإشعارات) تمر عبر دوال `app_*`. هذه الدوال تتحقق من رمز جلسة الدخول ومن دور المستخدم داخل الخادم نفسه. أما البيانات التشغيلية (المجموعات، التجمعات، التنبيهات، التقارير) فقراءتها مفتوحة للوحة التحكم.
للإنتاج الفعلي يُنصح بنقل الدخول إلى Supabase Auth.

> تنبيه: بعد تشغيل 04 تتوقف نسخة التطبيق القديمة المنشورة في `website/app` عن إرسال SOS والحضور، لأن الكتابة المباشرة على الجداول أُغلقت. أعيدي بناء التطبيق بأمر النشر.

## تحديث v3 / v4 — مميزات الحج (أكتوبر 2026)

### ما الجديد
**لوحة التحكم — قسم «الحج» (للإدارة والمشرفين):**
| الصفحة | ماذا تعرض | تكتب في القاعدة |
|---|---|---|
| المتابعة الذكية `smart.html` | مؤشر خطر الضياع لكل حاج، نظام الرفيق، الإجهاد الحراري، نبض الحشود في الجمرات وأفضل وقت للرمي، جاهزية الحافلة | أداة العرض (سيناريو منى / عرفة)، الفحص الذكي |
| حدود المشاعر `bounds.html` | من داخل حد عرفة/مزدلفة/منى ومن خارجه مع اتجاه الدخول، ساعات المبيت بمنى | تنبيه من هم خارج الحد |
| الصحة `health.html` | جرعات اليوم والفائتة، فحوص «أنت بخير؟»، بطاقة المسعف | إضافة دواء لحاج، إيقاف دواء، «أُعطيت»، توليد الجرعات |
| الأهل والرسائل `family.html` | روابط متابعة الأهل (بدون موقع دقيق) ورسائل المشرف المترجمة ومن قرأها | إنشاء/إيقاف رابط، إرسال رسالة بترجماتها |
| التشغيل `ops.html` | مصفوفة تجهيز ما قبل السفر، لوحة المفقودات، تقرير نهاية الحج + CSV | تسجيل غرض موجود، وُجد، سُلّم |
| الاستجابة للتنبيهات | بطاقة «نقطة اللقاء الذكية» لكل بلاغ | إرسال نقطة اللقاء للحاج ورفيقه |

صفحة الأهل العامة: `family.html?t=…` (تُفتح من زر «عرض» أو «نسخ» في صفحة الأهل والرسائل).

**تطبيق الحاج — شاشة «حجّي»** (البطاقة الذهبية في الرئيسية): دليل اليوم بلغة الحاج، عدّاد الطواف والسعي والجمرات بالترتيب الشرعي، مواقيت الصلاة (أم القرى) والقبلة، أدويتي وزر «أخذتها» وإضافة دواء، رسائل المشرف بلغتي، قائمة التجهيز، بلاغ المفقودات، وسؤال «أنت بخير؟» تلقائياً عند توقف الحركة ٢٥ دقيقة خارج المخيم.

### القاعدة
ملفات `database/07` إلى `13` **مطبّقة على قاعدة Supabase الحية** (38 جدولاً، 76 دالة `app_*`). للتركيب من الصفر: شغّلي 01 → 13 بالترتيب. كلها آمنة لإعادة التشغيل ما عدا ملفات البيانات التجريبية (02، 05، 10).

### التشغيل والنشر
**أسهل طريقة قبل العرض:** اضغطي مرتين على `جهّز_العرض.command`. يفحص التطبيق ويبنيه داخل `website/app`، ثم يشغّل اللوحة والتطبيق على http://127.0.0.1:8768 لمدة ساعتين ويفتحها في المتصفح.

1. **تجربة محلية فقط:** اضغطي مرتين على `تجربة_الموقع_محليا.command` ← http://127.0.0.1:8768/dashboard/login.html
2. **فحص كود التطبيق:** `تحقق_التطبيق.command` (النتيجة في `flutter_app/analyze.log`).
3. **النشر:** `نشر_عين_الحملة.command` يبني التطبيق داخل `website/app` ← اسحبي مجلد `website` إلى Netlify (Deploys).
   بدون إعادة النشر يبقى الموقع المنشور على الإصدار القديم.

### سيناريو العرض المختصر (١٠ دقائق)
1. دخول الإدارة `1010101010` ← **المتابعة الذكية** ← «سيناريو منى»: يتحرك الحجاج، ويظهر الحاج الباكستاني على بعد ٩٠٠ م وبطاريته ١٤٪ بأعلى خطر.
2. **الاستجابة للتنبيهات** ← افتحي بلاغه ← «نقطة اللقاء الذكية» ← إرسال.
3. «سيناريو عرفة» ← **حدود المشاعر**: حاجّان خارج حد عرفة مع اتجاه الدخول ← «تنبيه من هم خارج الحد».
4. **الصحة** ← «+ دواء لحاج» ← يظهر فوراً في تطبيق الحاج.
5. **الأهل والرسائل** ← «+ رابط للأهل» ← «عرض»: ما يراه الأهل (بدون موقع). ثم «+ رسالة للحجاج» بالعربية والإنجليزية والأردية.
6. تطبيق الحاج `1030303030` ← «حجّي»: عدّاد الطواف، «أخذتها» للدواء، الرسالة بلغته. وبحساب `2040404041` تظهر الرسالة بالأردية.
7. **التشغيل** ← تقرير نهاية الحج.

### حدود يجب ذكرها بصراحة
- حدود المشاعر في القاعدة **تقريبية للعرض** وليست الحدود الرسمية.
- الترجمة تُكتب يدوياً عند الإرسال؛ الترجمة الآلية والتسجيل الصوتي يحتاجان ربط خدمة خارجية.
- مواقع الحجاج في العرض تأتي من «أداة العرض» بدل GPS جوالات حقيقية (التطبيق يرسل GPS الفعلي عند استخدامه على الجوال).
- مواقيت الصلاة والتاريخ الهجري تُحسب على الجوال وقد يختلف التاريخ يوماً عن إعلان الرؤية.
